# UNIQUE DESIGN ARCHITECTURE PRO
## Обязательный слой проектирования главной страницы

Статус: архитектурная спецификация для интеграции в локальный AI-помощник Landing Studio. Этот документ задаёт обязательные правила генерации; сам по себе он ещё не подключает их к исполняемому коду.

## 1. Главный принцип

Landing Studio не должен генерировать сайты по схеме «один шаблон + другие тексты, цвета и фотографии». Для каждого нового проекта сначала проектируется самостоятельная визуальная концепция и композиция, затем под неё формируются секции и интерфейс.

Общие компоненты разрешены только как техническая основа. Они не определяют внешний вид всех сайтов.

## 2. Обязательный Design Brief

До генерации HTML помощник формирует внутренний brief:

- бизнес и продукт;
- аудитория, её задача и уровень знакомства с продуктом;
- главное целевое действие;
- характер бренда и эмоциональный тон;
- ключевые доказательства доверия;
- тип контента, который должен доминировать;
- ограничения по функциональности и контенту;
- выбранная архитектура первого экрана;
- объяснение, почему эта архитектура подходит нише.

Если данных недостаточно, использовать явно обозначенные гипотезы. Не выдумывать цены, отзывы, сертификаты, адреса, гарантии и характеристики.

## 3. Библиотека архитектур главной страницы

Выбирать не менее одной основной архитектуры и при необходимости одну вспомогательную. Не использовать один и тот же вариант по умолчанию.

1. **Product First** — товар, цена/характеристики и покупка в центре. Для магазинов и каталогов.
2. **Editorial / Magazine** — журнальная типографика, колонки, авторская подача. Для студий, брендов и экспертных услуг.
3. **Immersive Fullscreen** — полноэкранный визуальный сюжет. Для фотографии, искусства, событий и эмоциональных брендов.
4. **Asymmetric Canvas** — асимметричная композиция с несколькими зонами внимания. Для креативных и сервисных брендов.
5. **Catalog / Marketplace** — категории, поиск, подборки и товары видны сразу. Для широкого ассортимента.
6. **Split Utility** — разделённый экран с ясным предложением и инструментом действия. Для услуг, подбора и консультаций.
7. **Storytelling Scroll** — последовательный рассказ с управляемым ритмом секций. Для сложного продукта и бренда с историей.
8. **Modular Grid** — модульная сетка с несколькими равноправными сценариями входа. Для мультисервисных компаний.
9. **Brutalist / Experimental** — выразительная типографика и намеренная графическая смелость. Только если соответствует аудитории и задаче.
10. **Minimal Conversion** — минимум отвлечений, сильное предложение и одно основное действие. Для узких предложений и лидогенерации.

## 4. Правила выбора

- Выбор основывается на бизнес-модели, аудитории, содержании и основном действии, а не на случайном выборе.
- Для магазина ассортимент и путь к покупке важнее декоративного hero.
- Для портфолио первичны работы и визуальное доказательство качества.
- Для кофейни/ресторана первичны меню, продукт, атмосфера и способ посещения/заказа.
- Для салона первичны результат, услуги, мастера, примеры работ и запись.
- Для сложной техники первичны подбор, характеристики, сравнение и доверие.
- Не превращать каждую нишу в премиальный тёмный лендинг.

## 5. Антишаблонные ограничения

Не считать обязательными или универсальными:
- тёмный фон с золотыми акцентами;
- крупный serif-заголовок слева и изображение справа;
- одинаковую горизонтальную шапку;
- одинаковые pill-кнопки;
- декоративные орбиты, плавающие карточки и круглые бейджи;
- одинаковую последовательность секций.

Каждый из этих приёмов допустим только при обосновании в Design Brief.

Для двух соседних проектов нельзя повторять одновременно архитектуру hero, расположение основного визуала и характер типографической иерархии. Если сходство неизбежно из-за ниши, отличать проекты через композицию, контентную модель, навигацию, визуальный материал и интерактивность.

## 6. Генерация визуальной системы

Для каждого проекта отдельно определить:
- палитру: фон, поверхности, текст, акцент, состояния;
- типографику: display, body, интерфейсные размеры и шкалу;
- сетку, ширину контейнера и ритм отступов;
- форму карточек, кнопок, полей и навигации;
- стиль фотографии/иллюстраций/3D;
- графические мотивы и иконографику;
- motion-поведение и правила reduced motion.

Не переносить токены одного бренда в другой автоматически. Цвет и шрифт выбираются под задачу, контент и читаемость.

## 7. Структура страницы

Секции выбирать и упорядочивать под пользовательский сценарий. Не вставлять все блоки библиотеки подряд. Для каждого блока определить его функцию: привлечь внимание, объяснить ценность, доказать, помочь выбрать, снять возражение или привести к действию.

## 8. Контракт результата для генератора

Перед генерацией разметки сформировать объект-концепцию со следующими полями:

```json
{
  "designBrief": {
    "businessType": "",
    "audience": "",
    "primaryGoal": "",
    "brandCharacter": "",
    "contentPriority": []
  },
  "designDNA": {
    "primaryArchetype": "",
    "secondaryArchetype": "",
    "selectionRationale": "",
    "colorDirection": "",
    "typographyDirection": "",
    "imageDirection": "",
    "motionDirection": ""
  },
  "homepage": {
    "heroComposition": "",
    "navigationPattern": "",
    "sectionOrder": [],
    "primaryCTA": ""
  },
  "uniquenessCheck": {
    "templateReuseDetected": false,
    "repeatedPatterns": [],
    "differentiationActions": []
  }
}
```

Это формат внутреннего проектного brief, а не данные для публикации пользователю.

## 9. Проверка перед выдачей

Проверить:
- можно ли понять нишу и предложение за первые секунды;
- соответствует ли композиция содержанию;
- виден ли основной путь пользователя;
- не повторяет ли сайт без причины типовой hero;
- достаточно ли отличается визуальный характер от других проектов;
- читаемы ли текст и контраст;
- корректна ли мобильная версия от 320 px;
- работают ли ссылки, меню, CTA и формы;
- соблюдены ли prefers-reduced-motion и клавиатурная доступность.

Если проверка выявила шаблонность, пересобрать сначала композицию и контентную иерархию, а не ограничиваться сменой палитры.

## 10. Примеры направления для текущих ниш

- **DOMA TECH:** Product First / Catalog. Категории, подбор и сравнение техники; светлая или нейтральная технологичная система допустима, но не обязательна.
- **PHOTOGRAF:** Immersive Fullscreen / Editorial. Работы и истории доминируют над текстом.
- **PENKA:** Editorial / Modular Grid. Кофейная атмосфера, меню, выпечка и сценарий визита.
- **RAKI:** Product First / Storytelling. Продукт, категории, свежесть/приготовление, доставка и заказ.
- **HAIR:** Editorial / Split Utility. Результаты работ, услуги, мастера и запись.
- **Магазин телескопов:** Catalog / Product First. Категории оптики, сценарии наблюдений, подбор по уровню и сравнение характеристик.

Это стартовые гипотезы, а не жёсткие шаблоны. Каждая новая генерация должна пересматривать выбор по фактическим вводным.

## 11. Условие интеграции

Эта спецификация считается внедрённой в продукт только после того, как локальный AI-помощник:
1. формирует Design Brief и Design DNA;
2. использует их при создании структуры и HTML;
3. выводит выбранную концепцию в промте/результате;
4. выполняет антишаблонную проверку;
5. сохраняет совместимость с текущим форматом проекта и импортом JSON.

Не заявлять о полной автоматической уникальности, пока эти пункты не реализованы и не проверены тестовыми проектами.
